## 구현 전략 — 빅뱅 분해 대신 페이지 구성 레이어

monitor.js의 모든 렌더러는 이미 `if (!section) return` 가드가 있어 **DOM에 없는
섹션은 스스로 건너뛴다**. 이를 이용해 엔진(monitor.js)은 그대로 두고:

1. HTML 3장(`monitor.html`→`us_page`? 아님 신규 `landing/kr/us`)이 **각자 필요한
   섹션 마크업만** 갖는다.
2. `window.MULMIT_PAGE = "landing" | "kr" | "us"` 전역 하나로:
   - `loadCore()`가 그 페이지에 필요한 엔드포인트만 fetch (랜딩: overnight+
     indices+pension+assets 요약 / kr: KR 4종 / us: macro·assets·sectors·stress·weekend 제외 여부 결정)
   - `renderSkeleton()`의 SECTIONS 루프가 페이지 필터를 적용
     (korea-official은 kr, 나머지는 us)
   - jump-nav는 페이지 내 존재 섹션만 (기존 hidden 필터가 이미 처리)
3. 신규 CSS는 랜딩 히어로·헤더 티커·세션 배지에만 추가, 기존 섹션 스타일 재사용.

리스크가 큰 JS 모듈 분해는 하지 않는다. 파일이 더 커지면 그때 분리한다.
